## **Название задачи:**
Онлайн-магазин «Мобильный мир» - Настройка чтения с реплик и консистентность

## **Нефункциональные требования**

| **№** | **Требование**                                                                                                                              |
|:-----:|:--------------------------------------------------------------------------------------------------------------------------------------------|
|  1.   | Пользователи не должны иметь проблемы из-за лага репликации                                                                                 |     
|  2.   | Предполагается решение на базе Mongo DB.                                                                                 |     

## **Решение**

Будем рассматривать реализованное ранее решение - коллекция ProductLeftovers отделена от Products.

| **Операция чтения**                                        | **Тип реплики** | **Допустимый лаг репликации** | **Обоснование**                                                                                                              |
|------------------------------------------------------------|-----------------|------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| Основные характеристики товара                             | secondary       | до 30-60 сек                 | Эти данные почти не меняются, небольшая задержка не влияет на продажу.                                                       |
| Поиск товаров по категории/фильтрам                        | secondary       | до 30-60 сек                 | Эти данные почти не меняются, небольшая задержка не влияет на продажу.                                                       |
| Цена товара в карточке                                     | secondary       | до 10 сек                    | Цены могут обновляться, но не критично быстро. Небольшая задержка допустима.                                                 |
| Актуальная цена в момент оформления заказа                 | primary         |                              | Лаг репликации недопустим, тк нужна актуальная цена.                                                                         |
| Информация об остатках\гео-доступности в карточке товара   | secondary       | до 2-5 сек                   | Небольшой лаг не повлияет на продажи.                                                                                        |
| Проверка остатка при добавлении товара в корзину           | primary       |                              | Если бизнес-логика подразумеввает резервирование товара, то чтение должно быть максимально актуальным.                       |
| Проверка остатка при оформлении заказа                     | primary       |                              | Критична актуальность данных. Операция проверки и списания остатков должна быть атомарной.                                   |
| История заказов пользователя                               | secondary       | до 5–10 сек                  | Допустима легкая задержка.                                                                                                   |
| Детали заказа                                              | secondary       | до 5–10 сек                  | Информационные данные, их задержка некритична.                                                                               |
| Отображение статуса заказа                                 | secondary       | до 2 сек                     | Довольно критичная информация.                                                                                               |
| Проверка статуса перед выполнением логистики или списанием | primary       |                              | Нужны строго актуальные данные.                                                                                              |
| Создание уникальной активной корзины                       | primary         |                              | Чтобы не плодить дубликаты корзин, которые могут создать неконсистентность при дальнейших операциях пользователя с корзиной. |
| Получение активной корзины                                 | primary         |                              | Пользователь должен видеть отражение своих действий по добавлению\изменению кол-ва\удалению товаров в корзине.               |
| Получение не активной\архивной корзины                     | secondary         | до 30-60 сек                             | Это служебная информация, допустима задержка.                                                                                |
| Проверка корзины перед оформлением заказа.                 | primary         |                             | Формирование заказа должно быть на строго актуальных данных.                                                                 |
 
**Итого:**
- Всё, что влияет на покупку товара: остаток, деньги - читаем только с primary.
- Справочная \ историческая \ кешируемая информацию - читаем с secondary.
