## **Название задачи:**
Онлайн-магазин «Мобильный мир» - Выявление и устранение «горячих» шардов

## **Функциональные требования**

| **№** | **Действующие лица или системы**  | **Use Case**                                                                                 | **Описание**                                                                                         |
|:-----:|:----------------------------------|:---------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------|
|  UC1  | Система мониторинга               | Из-за категории «Электроника» произошла перегрузка одного из шардов MongoDB.                 | Система мониторинга должна обнаруживать "горячие" шарды.                                             |
|  UC2  | Инструменты SRE                   | Товары из популярных категорий могут создавать непропорциональную нагрузку на отдельные узлы | Инженеры по обеспечению доступности должны иметь механизмы автоматического перераспределения данных. |

## **Нефункциональные требования**

| **№** | **Требование**                                                   |
|:-----:|:-----------------------------------------------------------------|
|  1.   | Предполагается решение на базе Mongo DB.                         |     

## **Решение**

Проблему раздутых шардов по причине **категории** товаров мы минимизировали на первом этапе, отделив информацию об остатках от основной коллекции продуктов:
```puml
entity Product {
    * product_id: number <<generated>>
    --
    * name: text
    * category: text
    * price: number
    attributes: json
}

entity ProductLeftover {
    * product_id: number <<generated>>
    --
    * geo: text
    * quantity: number
    * updated_at: timestamp
}
```
Коллекция Products может быть эффективно кеширована, а коллекция ProductLeftovers - шардирована по product_id:
```javascript
sh.shardCollection(
    "db.ProductLeftovers", 
    {product_id: "hashed"}
)
```

Но в целом проблема горячих шардов может возникнуть по другим причинам, например, из-за популярного товара.

### Для детектирования перегруженной шард-ноды можно предложить

**1. Метрики нагрузки на шард:** CPU, DiskIO, WiredTiger Cache Pressure, оценить состояние очереди конкурентных апдейтов.
Для оценки использовать как встроенные инструменты mongo
Например:
```javascript
db.serverStatus().metrics.cpu
db.serverStatus().wiredTiger.cache["percentage of cache used"]
```
так и настроить экспорт в Prometheus.

**2. Метрики дисбаланса данных:** число и размеры чанков на шарде, Chunk Migration Rate.
Например:
```javascript
sh.status()
sh.printShardingStatus()
```

**3. Метрики распределения ключей шардирования:** частота использования ключа, распределение ключей.
С помощью:
```javascript
db.ProductLeftovers.aggregate()
```

**4. Метрики производительности операций:** 95, 99-перцентили операций обновления.
Например:
```javascript
db.serverStatus().opLatencies
```

**5. Метрики репликации:** оценить лаг репликации.
Например:
```javascript
rs.printSlaveReplicationInfo()
```

### Механизмы автоматического перераспределения данных
1. Встроенный балансировщик MongoDB
```javascript
sh.setBalancerState(true)
sh.setBalancerWindow("01:00", "05:00")  // мигрировать ночью
```
или запускать балансировщик при нагрузке.
2. Auto-Split
```javascript
sh.enableAutoSplit()
```
либо разрезание чанка по заданным правилам.
3. Range Tagging - привязать определенные товары к конкретным шард-нодам.
4. Использование Atlas-инсталляции и соответствующих инструментов балансировки данных.
5. Автоматическая оркестрация - ввод новых шардов при возрастании нагрузки+перебалансировка.
