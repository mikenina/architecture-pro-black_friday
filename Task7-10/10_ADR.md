## **Название задачи:**
Онлайн-магазин «Мобильный мир» - Миграция на Cassandra: модель данных, стратегии репликации и шардирования

**Специфика Cassandra:**
- репликация без ведущей ноды;
- есть механизмы восстановления согласованности;
- Consistent Hashing, шардирование на кольце токенов;
- AP: Availability - Partition Tolerance;
- eventual consistency;
- устойчивость к большим нагрузкам на запись;
- хорошо масштабируется горизонтально; быстрый решардинг.

## **Нефункциональные требования**

| **№** | **Требование**                                                                                                                              |
|:-----:|:--------------------------------------------------------------------------------------------------------------------------------------------|
|  1.   | Высокая отказоустойчивость (leaderless‑репликация).                                                                                         |     
|  2.   | Быстрое горизонтальное масштабирование без полного перераспределения данных. |     
|  3.   | Равномерное распределение данных.                                                                                  |     

## **Решение**

### Анализ требований к устойчивости

| **Сущность**            | **Осн. операции**                                                                                                                                                    | **Частота обновлений**                        | **Критичность доступности (запись)** | **Критичность целостности** | **Комментарий**                                                                                                             |
|:------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------|:-------------------------------------|:----------------------------|:----------------------------------------------------------------------------------------------------------------------------|
| Заказы (актуальные)     | - Быстрое создание заказов с одновременным списанием остатков. - Отображение статуса.                                                                                | Средняя \ очень высокая при пиковых нагрузках | Высокая                              | Высокая                     | Требуется сильная атомарность, применение Cassandra сомнительно.                                                            |     
| Товары (каталог)        | - Поиск товаров по категориям и фильтрация по диапазону цен. - Описание товара на странице продукта                                                                  | Низкая                                        | Средняя                              | Низкая                      | Cassandra не даёт преимуществ для статичного каталога.                                                                      |    
| Остатки                 | - Частые обновления остатков при покупках.                                                                                                                           | Очень высокая                                 | Очень высокая                        | Очень высокая               | Требуется сильная атомарность, применение Cassandra сомнительно.                                                            |
| Корзины                 | - Создание корзины, когда заходит гость или новый пользователь. - Получение текущей корзины. - Операции с товарами. - Изменение статуса. - Удаление архивных корзин. | Высокая \ очень высокая при пиковых нагрузках | Высокая                              | Средняя                     | Перенести в Cassandra: требуется высокая доступность записи.                                                                |
| История заказов         | - Поиск истории заказов конкретного пользователя. - Завершенные заказы присоединяются к коллекции.                                                                   | Средняя                                       | Средняя    | Средняя                     | Перенести в Cassandra: коллекция растет монотонно, при масштабировании данные будут легче перераспределяться, чем на Mongo. |
| Пользовательские сессии | - Сессии, события, действия на сайте.                                                                                                                                | Очень высокая                                 | Средняя                              | Средняя                     | Перенести в Cassandra: коллекция растет монотонно, при масштабировании данные будут легче перераспределяться, чем на Mongo. |

**Итого:** предполагаем гибридную архитектуру: сущности, создающие нагрузку на запись \ участвующие в массовых перемещениях, вынесем в Cassandra.
Сущности, чувствительные к целостности, оставим в MongoDb (с учетом рекомендаций, данных в предыдущих разделах).

### Описание сущностей в Cassandra
```cql
CREATE TABLE carts_by_user (
    user_id UUID,
    cart_id UUID,                 
    status TEXT,                  
    items LIST<FROZEN<cart_item>>,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    PRIMARY KEY (user_id, status, cart_id)
) WITH CLUSTERING ORDER BY (status ASC, cart_id DESC);
```

```cql
CREATE TABLE carts_by_session (
    session_id UUID,
    cart_id UUID,
    status TEXT,
    items LIST<FROZEN<cart_item>>,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    PRIMARY KEY (session_id, status, cart_id)
) WITH CLUSTERING ORDER BY (status ASC, cart_id DESC);
    AND default_time_to_live = 2592000; -- 30 дней
```

```cql
CREATE TABLE order_history (
    user_id UUID,
    created_at TIMESTAMP,
    order_id UUID,
    status TEXT,
    total DECIMAL,
    geozone TEXT,
    items LIST<FROZEN<order_item>>,
    PRIMARY KEY (user_id, created_at)
) WITH CLUSTERING ORDER BY (created_at DESC);
```

```cql
CREATE TABLE user_sessions (
    session_id UUID,
    event_time TIMESTAMP,
    event_type TEXT,
    payload MAP<TEXT, TEXT>,
    PRIMARY KEY (session_id, event_time)
) WITH CLUSTERING ORDER BY (event_time DESC)
  AND default_time_to_live = 2592000; -- 30 дней
```

### Оценка рисков

| **Сущность**                         | **Таблица**      | **Partition key**              | **Размер партиции**                                                                                                  | **Риск горячих партиций**                                                                | **Комментарий**                                                      |
|:-------------------------------------|------------------|:-------------------------------|:---------------------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------|:---------------------------------------------------------------------|
| Корзины                              | carts_by_user \ carts_by_session | user_id UUID \ session_id UUID | Одна корзина ≈ 1–10 КБ + очистка по ttl => приемлемо                                                                 | нет (если не бот)                                                                        |                                                                      |
| История заказов (только завершенные) | order_history           | user_id UUID                       | При 1000 заказов/пользователя и 1 КБ на заказ => ~1 МБ. При 100 000 заказов - 100 МБ (рекомендуемый предел партиции) | нет (заказ может делать только авторизованный пользователь, что минимизирует риск фрода) | Можно добавить бакет PRIMARY KEY ((user_id, bucket), created_at), bucket = year |
| Пользовательские сессии              | user_sessions           | session_id UUID                | При 10 000 событий/сессию и 200 байт на событие => ~2 МБ + очистка по ttl => приемлемо                                                               |        нет (если не бот)                                                                                    |                                                                      |

- UUID - случайный, высококардинальный идентификатор => минимизация горячих партиций и равномерное распределение.
- consistent hashing + vnodes гарантирует, что при добавлении узла данные перераспределяются локально, без глобальной перебалансировки (в отличие от MongoDB range-based sharding).

### Рекомендации по consistency level и стратегиям обеспечения целостности

| **Сущность**                         | **Таблица**   | **CL (Write)** | **CL (Read)**      | **Hinted Handoff** | **Read Repair** | **Anti-Entropy Repair** | **Обоснование**                                                                                                                                                                                                                                                                                                                |
|:-------------------------------------|---------------|:---------------|:-----------------------------|:-------------------|:----------------|:------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| 
| Корзины в UI                         | carts_by_*    | ONE \ QUORUM   | QUORUM    | Да                 | Да              | Да                      | У нас 2 основных сценария чтения корзин: показать в UI и при создании заказа. В случае UI возможно стоит пренебречь рисками рассинхрона реплик, и использовать CL(Write)=ONE (особенно при пиковых нагрузках). Anti-Entropy Repair предлагается выполнять из расчета, что по архивным корзинам еще пройдется скрипт аналитики. |
| Корзины перед checkout               | carts_by_user | QUORUM         | QUORUM            | Да                 | Да              | Да                      | При чтении корзины перед оформлением заказа - важно получить ее актуальное состояние. Для этого можно выполнить запись статуса с CL(Write)=QUORUM. А также заблокировать корзину от изменений с помощью Lightweight Transaction на время создания заказа в транзакционной СУБД.                                                |
| История заказов (только завершенные) | order_history |    QUORUM     | QUORUM | Да                 | Да              | Да                      | Данные долгоживущие; чтение\запись - средней интенсивности; требуется актуальное состояние (пользователь должен видеть правильную историю своих заказов).                                                                                                                                                                      |
| Пользовательские сессии              | user_sessions |   ONE         |   ONE   | Да                   | -               | Да                      | Очень высокая частота записи; чтение редкое (аналитика, отладка); низкая критичность целостности. Цель — максимальная пропускная способность.                                                                                                                                                                                  |
